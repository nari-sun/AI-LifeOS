# File Attachments MVP

RT-0011 は、CLI / GUI の会話入力に添付ファイルを渡し、回答時の一時コンテキストとして使えるようにするためのMVPです。添付ファイルは個人データとして扱い、公開用Git差分には含めません。

## Scope

MVPで扱う形式:

* `.txt`
* `.md`
* `.pdf`

MVPで扱わないもの:

* 画像、音声、動画、Office文書
* ZIPなどのアーカイブ
* 外部URLの取得
* 添付ファイル本文の自動memory保存
* 添付ファイルのベクトルDB化

## Storage Policy

添付ファイル本体は個人データです。保存する場合はGit管理対象外の領域に置きます。

候補:

```text
inbox/attachments/
conversations/YYYY/MM/YYYY-MM-DD_HHMMSS/attachments/
```

Git exclusion expectations:

* `inbox/` はGit管理しない
* `conversations/` はGit管理しない
* 添付ファイルから抽出した一時テキストもGit管理しない
* `docs/` には設計と仕様だけを置き、個人ファイル名や本文サンプルを残さない

添付ファイルは会話ログと同じくローカルPC内の個人データとして扱います。APIキー、秘密情報、本人確認書類などが含まれる可能性を前提に、公開用ファイルへコピーしません。

## Extraction

抽出方針:

* `.txt` / `.md`: UTF-8を優先してテキストとして読む
* `.pdf`: テキスト抽出可能なPDFだけを対象にする
* スキャンPDFや画像PDFのOCRはMVP対象外
* 抽出結果は回答生成時の一時コンテキストとして使う

制限:

* 1ファイルあたり最大 1 MiB まで読み込む
* 1会話ターンあたり最大 3 ファイルまで添付できる
* 抽出テキストは1ファイルあたり最大 12,000 文字で切り詰める
* 切り詰めた場合はユーザーに分かる形で表示する

エラー扱い:

* 未対応拡張子は読み込まない
* サイズ超過は読み込まない
* PDF抽出失敗時は本文なしとして扱い、ファイル名とエラー概要だけを返す
* 文字化けや空本文の場合は、回答に使えないことを明示する

## Temporary Context Use

添付ファイル本文は、その会話ターンまたは対象セッションの回答用コンテキストとしてのみ使います。

MVPでは以下をしません。

* `memory/long_term.md` へ自動追記する
* `journal/` へ添付本文を直接保存する
* `memory/search_index.sqlite3` へ添付本文を直接投入する
* 添付本文を将来会話の検索対象として恒久化する

添付内容から長期的に重要な情報をmemory化する場合は、通常の会話整理フローで、会話内に明示された事実だけを扱います。

## raw.md Recording Policy

`raw.md` には、添付ファイル本文を丸ごと貼り付けません。

記録する情報:

* 添付があったこと
* パスを除いたファイル名
* 対応形式
* 抽出成功 / 失敗
* 抽出文字数または切り詰め有無
* 会話内でユーザーが添付内容について述べた内容

記録しない情報:

* 添付ファイル本文全文
* 抽出済み一時テキスト全文
* 公開に不向きな絶対パス

必要に応じて、ローカルの非Git管理パスへの相対参照だけを残します。

ファイル名は、絶対パスを削除し、制御文字や区切り文字を置換し、長すぎる名前を切り詰めた安全な表示名だけを使います。ファイル名自体に氏名、住所、顧客名などが含まれる可能性があるため、将来のUIでは送信前に表示名を編集または非表示にできる余地を残します。

## File Intake Safety

CLI / GUI がファイルを受け取る時は、以下を守ります。

* ユーザーが明示選択したファイルだけを読む。
* ディレクトリを再帰的に読み込まない。
* シンボリックリンクやショートカットを保存先として追跡しない。
* 保存する場合は `inbox/attachments/` などGit管理外の領域に置く。
* 保存名は安全なbasenameに正規化し、既存ファイルを上書きしないよう衝突時にsuffixを付ける。
* `..` や絶対パスを含む入力を保存先パスとして使わない。
* 抽出に失敗したファイルは本文なしのメタデータだけを返す。

## CLI Behavior

CLIでは、ユーザーが明示的に指定したファイルだけを添付として扱います。

想定動作:

* ファイルパスを受け取る
* 拡張子、存在、サイズを確認する
* 読み取り可能な範囲だけ抽出する
* 回答前に添付数と抽出状態を表示する
* live会話中は `memory` / `journal` / `conversations` を勝手に編集しない
* finalize時に `raw.md` へ添付メタデータだけを記録する

CLIは自動でディレクトリ全体を読みません。ユーザーが指定していないファイルを探索対象にしません。

## GUI Behavior

GUIでは、ファイル選択ダイアログまたはドラッグ&ドロップで添付します。

想定動作:

* 対応拡張子だけ選択可能にする
* 添付リストにファイル名、種類、サイズ、抽出状態を表示する
* サイズ超過、未対応形式、抽出失敗を送信前に分かる形で表示する
* 送信後は、そのターンの回答コンテキストへ抽出テキストを渡す
* GUI操作中に `memory` / `journal` を直接編集しない
* セッション保存時は添付メタデータを保持し、本文の恒久保存は別ルールに従う

GUIはChatGPT公式Webや公式デスクトップアプリをスクレイピングしません。

## Safety Rules

* OpenAI APIを直接使わない
* `.env` やAPIキーを前提にしない
* 添付本文を公開用ファイルへ保存しない
* Git管理対象に個人データを入れない
* 抽出できない内容を推測してsummary / journal / memoryに書かない
* 失敗時は回答生成を止めるのではなく、使えなかった添付を明示する
