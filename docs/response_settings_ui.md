# RT-0015 Response Settings UI

## ステータス

RT-0015 は保留です。この文書は、現時点の判断材料と最小設計を整理するためのものです。今回の作業では UI 実装やバックエンド実装は行いません。

現時点の結論:

- GUI にモデル・応答設定パネルはまだ追加しない。
- 既存 Python ブリッジに接続されておらず、テストもない設定は GUI に出さない。
- 将来実装する場合も、初心者向けプリセットを優先し、Codex CLI の生オプションを直接見せない。

## 背景

ChatGPT 風の日常利用では、用途に応じて応答速度、品質、口調、推論の重さを切り替えられると便利です。

ただし AI-LifeOS は現在、Codex CLI と既存 Python スクリプトを中心に動いています。GUI の設定項目だけを先に増やすと、内部実装とズレた見せかけの設定になりやすいため、設定責務を先に分けます。

設定責務は大きく2つあります。

- 会話返答生成: 会話中に assistant 返答を作る。
- 記憶整理処理: セッション整理時に `summary.md`、`journal`、`memory`、検索 index を作成・更新する。

この2つは分けて扱います。日常会話用の軽い設定変更が、記憶整理の品質や安全境界を暗黙に変えてはいけません。

## 現在の実装参照

会話返答生成は Phase2.6 のアダプタを使っています。

```text
scripts/codex_conversation.py
model: gpt-5.4-mini
model_reasoning_effort: medium
service_tier: fast
features.fast_mode: true
sandbox: read-only
approval: never
```

GUI からは以下の流れで呼び出します。

```text
desktop/app
↓
Tauri command
↓
scripts/chat_gui_bridge.py
↓
scripts/codex_conversation.py
```

記憶整理処理は Phase2.5 / finalize 系の処理を使っています。

```text
scripts/process_chat.py
scripts/finalize_live_chat.py
model: gpt-5.5
model_reasoning_effort: xhigh
sandbox: workspace-write
approval: never
```

GUI では「整理して保存」操作からのみこの処理へ接続します。通常の会話返答設定とは別物として扱います。

## 責務分離

| 領域 | 目的 | 現在の書き込み範囲 | 設定の責任箇所 | GUI公開方針 |
| --- | --- | --- | --- | --- |
| 会話返答生成 | 直近会話と read-only memory context を使って assistant 返答を作る | アプリ側が `inbox/live/*.jsonl` に user / assistant 発言を書く。Codex は read-only | 会話エンジン | バックエンド対応後に、安全な応答プリセットだけ公開候補 |
| read-only memory context | `memory` / `journal` / `summary` の関連抜粋を会話プロンプトに入れる | 読み取り専用 | 会話エンジンと Phase3 検索 | GUIブリッジ対応と分かりやすい表示名ができるまで非公開 |
| 記憶整理処理 | live JSONL を `raw.md` 化し、`summary` / `journal` / `memory` / index を更新する | ローカル生成物を書き込む | finalize / Phase2.5 処理 | 日常会話の応答設定としては公開しない |
| Git commit | 明示された場合だけ公開用プロジェクトファイルを commit する | 公開用プロジェクトファイルのみ | 既存の明示commitオプション | 応答設定ではない |
| sandbox / approval | Codex 実行時の安全境界 | コマンド権限を制御する | 開発者・運用者向け設定 | 初心者向けGUI設定として公開しない |

## GUIから変更できる範囲

### 現時点

RT-0015 時点では、GUI からモデル・応答設定を変更できるようにしません。GUI は既存バックエンドのデフォルト設定を使い続けます。

GUIで許可される操作は、既存の範囲に留めます。

- 新規チャットを開始する。
- メッセージを送信する。
- セッションを保存する。
- 既存ルール内でセッションを再開する。
- 既存 finalize 処理で「整理して保存」する。

### 将来の最小候補

再評価条件を満たした後、最初に GUI へ出す候補は、会話返答生成だけに効く初心者向けプリセット1つです。

候補:

| プリセット | ユーザー向け意味 | バックエンドの対応方針 |
| --- | --- | --- |
| 標準 | 日常利用向けのバランス | 中央のデフォルト設定を使う |
| 高速 | 待ち時間を短くしたい時 | 実装・テスト済みの場合だけ、会話用経路で reasoning や fast tier を軽くする |
| 丁寧 | 急がず慎重に答えてほしい時 | 実装・テスト済みの場合だけ、会話用経路で reasoning を重くする |

制約:

- GUI はプリセットIDだけを送る。
- model名、reasoning effort、service tier、fast mode などの具体値はバックエンド側の allowlist で管理する。
- 不明なプリセットIDは失敗扱いにする。デフォルトへフォールバックする場合も、その仕様を明示する。
- プリセットは会話返答生成だけに効かせる。
- プリセットで記憶整理処理のモデルや reasoning effort を変えない。

## まだGUIに出さない設定

以下は、バックエンド対応、入力検証、テスト、文書化が揃うまで GUI に出しません。

- 生の model id 選択。
- 生の `model_reasoning_effort` 選択。
- 生の `service_tier` 選択。
- `features.fast_mode` のトグル。
- 口調・人格プリセット。
- 最大コンテキスト件数。
- read-only memory context のオン・オフ。
- 記憶整理処理の model / reasoning 設定。
- sandbox mode。
- approval policy。
- commit 動作。

特に口調設定は、見た目だけ先に作りやすい項目です。現在の会話プロンプトには「自然に返答する」程度の指示はありますが、ユーザー向けの安定した口調契約はまだありません。プロンプト設計、保存方針、テストが決まるまで非公開にします。

## 記憶整理処理の方針

記憶整理処理は応答スタイル設定ではありません。長く残るファイルを更新するため、通常会話より厳しい設定を維持します。

- 専用の記憶整理モデル設定を使う。
- `workspace-write` は既存 finalize 経路に限定する。
- Git commit は既存の明示操作以外では実行しない。
- 会話用プリセットによって `summary` / `journal` / `memory` 抽出の品質を下げない。

将来、記憶整理側の設定を変更できるようにする場合も、日常会話のGUIトグルではなく、開発者・運用者向け設定として扱います。

## 実装前の必須条件

GUI応答設定を実装する前に、以下を満たす必要があります。

- RT-0008 と RT-0009 が完了し、通常の送信・停止・履歴再開が安定している。
- RT-0013 または同等のジョブ状態表示が完了し、記憶整理中に設定変更できない制御がある。
- Python ブリッジが会話返答用プリセットIDを受け取り、allowlist で検証できる。
- フロントエンドは、ブリッジが対応していない設定を表示しない。
- 各プリセットが会話返答生成だけを変えることをテストする。
- 記憶整理処理が専用設定を使い続けることをテストする。
- 表示するプリセットと非対象範囲を文書化する。
- UI 文言は model名ではなく「速い」「標準」「丁寧」のようなユーザー結果で説明する。

## 非目標

RT-0015 では以下を実装しません。

- 設定画面。
- モデルピッカー。
- 口調ピッカー。
- config ファイル移行。
- セッションごとの設定保存。
- GUIからの記憶整理モデル切り替え。

これらは、バックエンド契約が安定してから再評価します。
